1. https://git-scm.com 安装Git，无脑next，直到出现`Git Bash Here`

2. 告诉Git你是谁，一次配置 终身有效 以后所有仓库都用这个名字
git config --global user.name "diy名字"
git config --global user.email "当时注册 GitHub 的邮箱"

3. 让电脑免密码进门 只做一次
ssh-keygen -t ed25519 -C "同上邮箱"   # 然后一路回车
把 \.ssh\id_ed25519.pub 打开 → 全复制 → GitHub 头像 → Settings → SSH and GPG keys → New SSH key → 贴进去 → Add
    你电脑里存着“私钥”（不能泄露），GitHub 存着“公钥”（可公开）
    你电脑保存私钥，GitHub 保存公钥。连接时，GitHub 通过你上传的公钥，验证你电脑里对应私钥生成的签名；验证通过，就确认是你本人。SSH 连接本身也会加密传输。
    公钥的作用就是让 GitHub 能验证“发起这次认证的人，确实持有对应私钥”。私钥签名，公钥验证签名
    只负责“开门”和“加密隧道”，跟仓库内容无关。

4. git clone git@github.com:用户名/仓库.git   # 远程→本地，自动生成文件夹
git clone 会自动把远程仓库整个搬下来，并在你当前所在的目录里新建一个同名文件夹（名字就是仓库名），里面已经包含：所有文件 + 完整的 .git 历史目录
如果选择https，会自动跳出登录窗口让你输入验证。

5. cd 仓库文件夹                            # 进去再干活
你换文件夹，Git 就换仓库；无需重启、无需配置，自动识别（从你现在所在的目录开始，一路往上层目录找，直到碰见 .git 这个文件夹）。

6. 三部曲
git add . 或 git add 具体文件               # 把改动放进“购物车”（如果你已经执行过 git add，那么这些已暂存的改动不会出现在 git diff 里，要用 git diff --cached 看）
git commit -m "一句话说明" # 购物车结账，生成一条历史
git push                 # 把历史推到 GitHub，网页实时刷新

7. 其他改动
注意：Git 不管空抽屉，放张纸再关抽屉（纸＝任意文件，如 ".gitkeep" 只是大家约定俗成的名字，本质是“一张废纸”）；注意：git add 空目录名 会报错，必须指定具体文件。
新建文件（夹） → 先建文件 → git add . → commit & push
改文件 → 直接保存 → git add . → commit & push
删文件 → git rm 文件名 → commit & push
改文件夹名 → git mv 旧名 新名 → commit & push
把 A/a.py 挪到 C/a.py（C 原来没有也会自动出现） → git mv A/a.py C/a.py → commit & push

8. 反悔
还没 commit：`git restore .`  命令作用域 = 当前仓库的全部文件，如果你 cd 到某个子文件夹再执行，也仍然还原整个仓库的所有改动，而不仅仅是这一层文件夹
已 commit 未 push：`git reset --hard HEAD~1  # 退到上条历史（代码也回退）想退 3 步就 HEAD~3`
已经push：`git revert <某次提交哈希>` 不删历史，只追加“反操作”，会生成一个新 commit，只针对那一次提交的改动做“反操作”，后面别人再新的提交完全不受影响，历史保持完整，大家都能正常 pull

9. 换项目
一个文件夹就是一个独立仓库，想换项目就 cd 进出；本地没有才需要再 git clone
只要 cd 进这个仓库的任意子目录（包括根目录），执行git pull，Git 都会从当前目录一直向上找到 .git 文件夹，然后去拉这个仓库的远程更新。
git pull 会把远程最新提交拉到本地，并尝试与当前分支合并。如果没有冲突，通常你会得到包含远程最新内容的本地仓库；若你本地也有修改，可能需要先处理冲突。
还没冲突前，想放弃本地改动，直接跟远程走，`git restore .`; `git pull`
已经冲突后，手动改文件：保留自己 / 保留远程 / 两边都要 / 自己重写，四种选法都一样，都是：改文件, `git add` ; `git commit`
线上新增的文件/文件夹 → 本地自动出现
线上被删的文件/文件夹 → 本地自动删除
线上修改的内容 → 本地对应文件自动更新
完成后，本地根目录就和线上完全一致（除了你本地未提交的改动）。

10. 常用
git status               # 看现在啥情况
git log --oneline        # 看历史快递单
git diff                 # 查看差异
git diff（不带参数）只比较“工作区 vs 暂存区”
git diff --cached              # 暂存区 vs 最后一次提交
q 退出（回到命令行）
空格 向下翻页
b 向上翻页
回车 向下滚动一行
git pull                 # 上班先拉同事最新代码，随时可按，只对当前目录所属的那个仓库生效，如果本地也改了同一行，Git 会提示冲突，解决后再 commit 即可。

11. 大致流水账
如果线上仓库已存在，你本地从零开始。需要克隆，仅此一次。
cd C:\Users\yikai\PycharmProjects          # 放项目的父目录
git clone git@github.com:yikai1998/online-notes.git
如果线上仓库已存在，你本地也存在过。从这里开始。
cd .. 之类，来到父目录
cd online-notes                            # 自动生成（导航至）文件夹
每天开工时都输入git pull， 为了先同步（防止冲突）
以后每天只需要
git pull                   # 拿最新
改一行字 → 保存 【各种操作，手动直接前端鼠标操作】
git add 文件               # 或 git add .
git commit -m "简述"
git push                   # 完事
