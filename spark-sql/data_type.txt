Spark / Databricks SQL 嵌套数据速查

STRUCT：col.field
MAP：col['key'] 或 element_at(col, 'key')
ARRAY：col[0] 或 element_at(col, 1)
JSON 字符串：col:path 或 get_json_object(col, '$.path')
VARIANT：col:path::TYPE 或 col:path?::TYPE

STRUCT
就是“结构体/对象/一行数据”，像{"a":1,"b":"x"} 或 Python 里的 dict 或“数据库表里的单行”，包含一组有名字的字段
SQL类型: STRUCT<a INT, b STRING>
```sql
data.accountManager
data.user.name
```

MAP
就是“字典”，一堆key-value键值对，比如{"a":10, "b":20}
和struct区别：map的key一般可以是任意值（字符串、数字，不需要提前写死），struct的key字段是表结构里提前定义好的
SQL类型: MAP<STRING, INT>
m['say']
element_at(m, 'say')

ARRAY

arr[0] 是第一个
arr[1] 是第二个
element_at(arr, 1) 是第一个
element_at(arr, -1) 是最后一个

JSON 字符串

raw:accountManager
get_json_object(raw, '$.accountManager')
get_json_object(raw, '$.user.name')
get_json_object(raw, '$.items[0].price')

STRUCT 不要绕 JSON：

推荐：data.accountManager
不推荐：get_json_object(to_json(data), '$.accountManager')

VARIANT

v:accountManager
v:user.name
v:items.price
v:price::DOUBLE
v:price?::DOUBLE

类型转换

expr::TYPE 等价于 CAST(expr AS TYPE)
expr?::TYPE 等价于 TRY_CAST(expr AS TYPE)

例子：

'20'::INT 返回 20
'abc'?::INT 返回 NULL

from_json

JSON 字符串转强类型：

from_json(raw, 'STRUCT<accountManager: STRING, age: INT>')

然后取字段：

data.accountManager
data.age

to_json

强类型转 JSON 字符串：

to_json(data)

常见坑

get_json_object 输入是 JSON 字符串，返回 STRING。

data 是 STRUCT：

用 data.accountManager
不用 get_json_object(data, '$.accountManager')

ARRAY 下标：

arr[0] 是第一个
element_at(arr, 1) 是第一个

ARRAY<BOOLEAN> 不能 .final。

错：

element_at(from_json(json, 'ARRAY<BOOLEAN>'), -1).final

对：

element_at(from_json(json, 'ARRAY<STRUCT<final: BOOLEAN>>'), -1).final

最终记忆：

STRUCT 用 .
MAP 用 ['key']
ARRAY 用 [0] 或 element_at
JSON 字符串用 : 或 get_json_object
VARIANT 用 :
转类型用 ::
安全转类型用 ?::



参考链接：https://docs.databricks.com/aws/en/sql/language-manual/data-types  

```txt
: 用来“取json路径字段”，:: 是“强制转类型”，?:: 是“安全转类型”（失败就null）
原生/support-variant/raw 字段访问用 冒号
struct/schema/cast出来的 字段访问用 点

结构化数据（struct/array/map）：用 .field 或 ['field']（对 struct 也常可用）
JSON 字符串/variant：用 JSON 函数/JSON path（比如 get_json_object、: 等）
```
```
get_json_object(to_json(sf.data), '$.accountManager')
你的字段 data 是 struct 类型（或 map），直接用 :字段名 取子字段最自然。
get_json_object 实际要操作 string 类型。如果参数不是字符串（而是struct），就会报错。
第一个sf.data:accountManager是Spark为struct/map字段提供的语法糖，推荐优先用
```
```
: 链式适合“在 VARIANT/JSON 里走路径”，返回还是 VARIANT，所以能一直写下去
当列已经是 Spark 的强类型（struct/array/map）时，用 .
element_at(from_json(get_json_object(to_json(kc.data), '$.decisions'), 'array<boolean>'), -1).final
```

- VARIANT  
  Represents semi-structured data.
  

```txt
1. array
就是“数组”，像 [1,2,3]，也可以是 ["a", "b", "c"]
每项类型一般相同
SQL类型: ARRAY<STRING>, ARRAY<INT>, ARRAY<STRUCT<...>>...
2. struct
就是“结构体/对象/一行数据”，像{"a":1,"b":"x"} 或 Python 里的 dict 或“数据库表里的单行”
包含一组有名字的字段
SQL类型: STRUCT<a INT, b STRING>
3. map
就是“字典”，一堆key-value键值对，比如{"a":10, "b":20}
和struct区别：map的key一般可以是任意值（字符串、数字，不需要提前写死），struct的key字段是表结构里提前定义好的
SQL类型: MAP<STRING, INT>
4. variant（或有的库叫“any”/“json”）
最包容的类型，啥都能装进来！
你往里面塞个[1,2]变成array，塞个{a:1}变成struct/map，塞个"abc"是字符串，甚至可以嵌套。
真实含义就是“我不知道到底是啥，但保证能装下json任何结构的数据类型”。
```
